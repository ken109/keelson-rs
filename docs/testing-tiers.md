# The four testing tiers

keelson's goal for testing is blunt: **every construct the library declares is
exercised, alone and in combination, and that claim is proven numerically
rather than believed.** "Every query imaginable" over a recursive grammar is
infinite; what is achievable — and what these tiers deliver — is that the
declared surface is enumerated, driven, and measured.

Each tier answers a question the others cannot. Wherever a tier judges SQL, the
judge is independent of the code under test: the dialect's real parser
(`pg_query` bundles PostgreSQL's own; `sqlite3-parser` is a port of SQLite's
grammar; `sqlparser` is a generic parser used advisorily for MySQL), and — when
compiled in — a real engine `PREPARE`ing the statement. See
`crates/keelson-sqlcheck/src/lib.rs` for what each judge is and how far it is
trusted.

| tier | question it answers | where it lives |
| ---- | ------------------- | -------------- |
| A — intent | does each construct render as the SQL *we meant*? | each dialect's `tests/grammar_*.rs` |
| B — combinatorial | do constructs still hold together in combination? | each dialect's `tests/combinatorial.rs` |
| C — property | do randomly-shaped query trees uphold the invariants? | `keelson-psql/tests/property.rs` |
| D — coverage gate | did A–C actually exercise everything we declare? | `keelson-sqlcheck/src/coverage.rs` + `coverage/` |

## Tier A — intent

A hand-written walk of each statement's production in the dialect's reference
manual, one construct at a time. Every case builds a query, has the dialect's
grammar (and a real engine, when compiled in) accept the output, and compares
it against an expected string **derived from the manual** — never pasted from
the builder's own output, which would only assert that the code equals itself.

## Tier B — combinatorial

Clause *presence* driven as a cross product — tens of thousands of statements
per dialect — because the bugs worth finding live in interactions: a clause
that renders in the wrong order once another is present, or an argument that
silently binds to the wrong placeholder because an earlier clause claimed its
slot. Expectations come from manual-derived fragments assembled in the
manual's clause order (mysql, sqlite) or from inspecting the parse tree for
exactly the clauses asked for (psql, where the parse tree is trustworthy).

## Tier C — property

Random query *trees* — nested sub-queries, chained operators, stacked clauses
— generated by proptest, each checked against the grammar (and engine, when
available) plus the structural invariants: placeholder numbering matches the
argument vector, building twice is deterministic, clones build identically.
Shapes no human would think to write; shrinking turns a failure into a minimal
counterexample.

## Tier D — the coverage gate

Tiers A–C generate and judge SQL; Tier D is the ledger that proves what they
judged. It answers the question none of the others can: **across every SQL
string the suites accepted, which grammar constructs actually appeared?** Rust
line coverage cannot answer it — a line can run without the construct
appearing in the output — so Tier D measures from the SQL side:

1. **Record.** With `KEELSON_SQLCHECK_RECORD=<dir>` set, every SQL string a
   judge accepts is appended to `<dir>`, dialect-tagged (one file per test
   process; see `keelson-sqlcheck/src/record.rs`). Zero overhead when unset.
2. **Replay and measure.** The gate replays the recording against a
   checked-in **manifest** of every construct each dialect claims to render —
   `crates/keelson-sqlcheck/coverage/<dialect>.manifest`, one entry per
   construct, each naming the keelson API that produces it. psql statements
   are parsed with `pg_query` and the parse tree is walked for node kinds and
   discriminating fields; mysql and sqlite have no equivalent inspectable
   parser, so their tier is **token-level** (keyword signatures per
   construct), and the manifests say so plainly.
3. **Fail loudly.** A declared construct that never appeared fails the run,
   listing the construct and the API that would exercise it. Constructs that
   are observed but undeclared are reported (not fatal), so the manifest
   cannot silently rot. Constructs deliberately not rendered live in
   `coverage/<dialect>.exclusions`, each with a self-contained reason — the
   gate is green today *and* the exclusions are auditable.

The manifests are the long-lived deliverable: adding a construct to a dialect
without adding it to the manifest means the gate never guards it, and adding it
to the manifest without a test means the gate fails until a test exists.

### Running Tier D locally

Two commands — record a full test run, then gate it:

```sh
KEELSON_SQLCHECK_RECORD=$PWD/target/sqlcheck-record cargo test --workspace
cargo run -p keelson-sqlcheck --bin coverage-gate -- target/sqlcheck-record
```

(These are also the exact commands CI runs. Delete the directory before
re-recording; the recorder appends. The path must be absolute — each test
binary runs with its own crate directory as the working directory, so a
relative path scatters the recording across `crates/*/target/`.)

Exit status 0 means every declared construct was exercised. The `live-docker`
feature is not needed: recording hooks the grammar judges, which run on a plain
`cargo test`.

### Running the engine tier locally

```sh
cargo test --workspace --features keelson-sqlcheck/live-docker
```

Each test binary starts one PostgreSQL and one MySQL container on first use
and removes them when it exits — via an `atexit` hook for normal exit and the
testcontainers `watchdog` for Ctrl-C, because testcontainers 0.27 has no
reaper of its own. A run should leave `docker ps -a` as it found it. A process
killed outright (SIGKILL, power loss) can still leave containers behind;
remove them with

```sh
docker rm -f $(docker ps -aq --filter "label=org.testcontainers.managed-by=testcontainers")
```

To skip the per-binary startups entirely — one server for the whole run, which
is faster and has nothing to leak — point the judges at servers you manage:

```sh
docker run -d --name keelson-live-psql -e POSTGRES_PASSWORD=postgres \
  -p 5433:5432 postgres:17-alpine
docker run -d --name keelson-live-mysql -e MYSQL_ALLOW_EMPTY_PASSWORD=1 \
  -e MYSQL_DATABASE=test -p 3307:3306 mysql:8.4

KEELSON_LIVE_PSQL_URL="postgresql://postgres:postgres@127.0.0.1:5433/postgres" \
KEELSON_LIVE_MYSQL_URL="mysql://root@127.0.0.1:3307/test" \
cargo test --workspace --features keelson-sqlcheck/live-docker
```

Each URL must name a database the tests may fill with the shared schema. The
first binary to reach the server applies it under a server-side lock —
concurrently launched binaries (e.g. nextest) are safe — and later binaries
find it present and skip it. Keep the image versions in step with
`PSQL_IMAGE_TAG` / `MYSQL_IMAGE_TAG` in `keelson-sqlcheck/src/live.rs`, or the
judge runs against a server other than the one CI answers to.

### When the gate fails

The report names each unexercised construct and its API. There are exactly two
honest responses:

- **Add a test** in the owning dialect's `tests/grammar_*.rs` that renders the
  construct through a judged assertion (`assert_sql` / the `common` helpers /
  `built`). This is the normal case: the construct works, nothing proved it.
- **Add a reasoned exclusion** to `coverage/<dialect>.exclusions`, moving the
  entry out of the manifest. Only for constructs that genuinely cannot appear
  in a judged corpus — grammar defaults that are deliberately unrepresentable
  (`SELECT ALL`), or constructs a judge itself refuses (see the
  `frame.from_unbounded_following` entry for the shape of such a reason).
  An exclusion whose reason does not survive a reader's "why?" is a hole, not
  an exclusion.

Deleting the manifest entry is not one of the options.

### The meta-tests

A gate that cannot fail is a green light wired to nothing, so
`keelson-sqlcheck/tests/coverage_gate.rs` feeds the analyzer a corpus missing
a declared construct and asserts the gate fails *naming it* — plus the
converse (exercised constructs are not reported missing), and failure on stale
or corrupt recordings.
